Practical solutions for common API development tasks using ergo. Each
recipe follows a **Problem → Solution → Explanation** structure with
working code examples for both standalone composition and declarative
ergo-router configuration.

## Available Recipes

| Recipe | Problem |
| ------ | ------- |
| [Pagination](/recipes/pagination/) | Offset and cursor pagination with RFC 8288 Link headers |
| [Testing Patterns](/recipes/testing-patterns/) | Reliable HTTP testing with ephemeral ports and graceful shutdown |
| [Custom Headers](/recipes/custom-headers/) | Adding response headers from middleware and execute handlers |
| [Error Handling](/recipes/error-handling/) | Custom error responses, extension members, and correlation IDs |
| [File Upload](/recipes/file-upload/) | Handling multipart file uploads with size limits and parsed content |
| [Multi-Auth Strategies](/recipes/multi-auth/) | Per-route auth overrides, optional auth, and API key authentication |
| [PATCH Semantics](/recipes/patch-semantics/) | RFC 7386 merge-patch and RFC 6902 JSON Patch with strict enforcement |
| [Graceful Shutdown](/recipes/graceful-shutdown/) | Server lifecycle with database connections and resource cleanup |
| [Debug Tracing](/recipes/debug-tracing/) | Finding which middleware rejected a request using pipeline debug mode |
| [Mixed-Auth CORS & CSRF](/recipes/mixed-auth-cors-csrf/) | Configuring CORS and CSRF together for browser and token-based clients |

## When to Use Recipes vs. Middleware Guides

- **Middleware guides** document individual middleware — options, return
  values, error responses, and per-middleware usage examples.
- **Recipes** solve cross-cutting problems that involve multiple
  middleware or patterns that don't belong to a single middleware page.
