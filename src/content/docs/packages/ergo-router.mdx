## Installation

```bash
npm install @centralping/ergo-router @centralping/ergo
```

`@centralping/ergo-router` has a peer dependency on `@centralping/ergo`.

## Overview

ergo-router provides path-based request dispatch built on
[`find-my-way`](https://github.com/delvedor/find-my-way) with automatic REST
compliance and a declarative pipeline builder.

### Automatic REST Behavior

| Behavior | Standard | Description |
| -------- | -------- | ----------- |
| 405 + Allow | [RFC 9110 §15.5.6](https://www.rfc-editor.org/rfc/rfc9110#section-15.5.6) | Requests to a known path with an unsupported method receive `405` with an `Allow` header listing valid methods |
| HEAD derivation | [RFC 9110 §9.3.2](https://www.rfc-editor.org/rfc/rfc9110#section-9.3.2) | HEAD requests automatically derive from GET handlers |
| OPTIONS | [RFC 9110 §9.3.7](https://www.rfc-editor.org/rfc/rfc9110#section-9.3.7) | OPTIONS requests return `Allow` header with supported methods |
| PATCH required | Custom | Routes with PUT must also register PATCH (or explicitly opt out) |

### Transport Middleware

| Middleware | Description | Standard |
| ---------- | ----------- | -------- |
| Security headers | HSTS, CSP, X-Content-Type-Options | [RFC 6797](https://www.rfc-editor.org/rfc/rfc6797) |
| CORS | Cross-Origin Resource Sharing | [Fetch Standard](https://fetch.spec.whatwg.org/#http-cors-protocol) |
| Rate limiting | Global rate limiter with 429 responses | [RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585#section-4) |
| Request ID | X-Request-Id generation and propagation | Convention |

### Pipeline Builder

Declaratively compose ergo middleware for each route:

```js
import createRouter from "@centralping/ergo-router";

const router = createRouter({
  defaults: {
    accepts: { types: ["application/json"] },
  },
});

router.post("/users", {
  authorization: { strategies: [bearerStrategy] },
  validate: { body: userSchema },
  execute: createUser,
});
```

The `execute` function is the route handler — most handlers use
`(req, res, acc)`, and advanced handlers can also read a fourth argument
`responseAcc`. `acc` is the domain accumulator carrying middleware outputs
(auth identity, parsed body, etc.) plus router-seeded route params
(`acc.route.params`). See the
[Accumulator Reference](/concepts/accumulator/) for the complete shape, or the
[Architecture](/concepts/architecture/) page for the two-accumulator pipeline
model.

### Config Resolution

When a route registers a config key that also appears in `defaults`, the
route value **replaces** the default entirely — it does not merge.

#### Resolution Order

For each config key, the pipeline builder resolves the effective value
using route config first, then defaults:

| Route value | Default value | Resolved value | Effect |
| --- | --- | --- | --- |
| `undefined` (omitted) | `{...}` | `{...}` | Inherits default |
| `false` | any | disabled | Explicitly disables — removes from pipeline |
| `true` | any | `{}` | Enables with empty options |
| `{...}` (object) | `{...}` | route `{...}` | Route **replaces** default entirely |

#### Replace vs. Extend

Setting a config key on a route **replaces** the default — properties are
not deep-merged:

```js
const router = createRouter({
  defaults: {
    authorization: {
      strategies: [bearerStrategy, apiKeyStrategy],
    },
  },
});

// ⚠️ This route loses bearerStrategy and apiKeyStrategy —
// the route value replaces the default entirely
router.get("/admin", {
  authorization: { strategies: [basicStrategy] },
  execute: adminHandler,
});
```

To **extend** defaults rather than replace them, spread the default values
into the route config manually:

```js
const authDefaults = {
  strategies: [bearerStrategy, apiKeyStrategy],
};

const router = createRouter({
  defaults: { authorization: authDefaults },
});

// ✓ This route has all three strategies
router.get("/admin", {
  authorization: {
    strategies: [...authDefaults.strategies, basicStrategy],
  },
  execute: adminHandler,
});
```

<Aside type="tip" title="The use key is an exception">
  The `use` key follows **concatenation** semantics instead of replacement —
  `defaults.use` entries run first, then route-level `use` entries. Setting
  `use: false` on a route disables all custom middleware (both defaults and
  route-level). See the
  [Custom Middleware recipe](/recipes/custom-middleware/) for details.
</Aside>

<Aside type="note" title="Auto-inclusion and false">
  Setting a key to `false` disables it even when the pipeline builder would
  auto-include it based on HTTP method. For example, `body: false` on a
  POST route prevents body parsing, and `url: false` on a GET route prevents
  URL parsing.
</Aside>

### Application Middleware

`router.use(...fns)` registers middleware that runs before every route
pipeline. Application middleware is prepended to each route's pipeline
array, executing before all four stages (Negotiation, Authorization,
Validation, Execution):

```js
router.use((req, res, acc) => {
  res.on("finish", () => {
    console.log(`${req.method} ${req.url} ${res.statusCode}`);
  });
});
```

`use()` returns the router, so calls can be chained:

```js
router
  .use(requestLogger)
  .use(requestMetrics)
  .get("/users", { execute: listUsers });
```

<Aside type="caution" title="Array pipelines only">
  Application middleware applies to routes registered with declarative
  config objects or pipeline arrays. Routes registered as a single handler
  function bypass the pipeline entirely — application middleware does not
  run for them.
</Aside>

<Aside type="tip" title="Per-route vs. application middleware">
  `router.use()` is **application-level** — it runs before all four
  pipeline stages on every request. The `use` config key is
  **per-route** — it inserts middleware after Stage 3 (Validation) and
  before Stage 4 (Execution). See the
  [Custom Middleware recipe](/recipes/custom-middleware/) for the
  per-route `use` key.
</Aside>

### Route Options

Declarative route configs accept per-route options that control pipeline
behavior. These options are extracted from the config object and passed
to the auto-wrap layer — they do not correspond to pipeline middleware.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `noSend` | `boolean` | `false` | Skip the automatic `send()` call after the pipeline completes. The handler is responsible for writing the full HTTP response. |
| `send` | `object` | — | Per-route options passed to `send()`. Overrides router-level `send` defaults. |
| `catchHandler` | `function` | — | Per-route error handler. Receives `(req, res, err)` when the pipeline throws. Overrides router-level `catchHandler`. |

#### `noSend` — Manual Response Control

When `noSend: true`, ergo-router runs the full pipeline (including OTEL
tracing if configured) but does not call `send()` after the pipeline
completes. The handler must write headers, the status code, and the
response body directly via Node.js `res` methods.

Use cases: streaming responses, Server-Sent Events, file downloads, or
any response format that `send()` does not support.

```js
router.get("/events", {
  noSend: true,
  authorization: { strategies: [bearerStrategy] },
  execute: (req, res, acc) => {
    res.writeHead(200, {
      "Content-Type": "text/event-stream",
      "Cache-Control": "no-cache",
      Connection: "keep-alive",
    });

    const interval = setInterval(() => {
      res.write(`data: ${JSON.stringify({ ts: Date.now() })}\n\n`);
    }, 1000);

    req.on("close", () => {
      clearInterval(interval);
      res.end();
    });
  },
});
```

<Aside type="caution" title="Full response responsibility">
  With `noSend: true`, the pipeline and OTEL spans still run, but the
  framework does not write any HTTP response. Your handler must call
  `res.writeHead()`, `res.write()`, and `res.end()` — if you don't,
  the client connection will hang.
</Aside>

### Pagination

The `paginate` config key wires a two-sided contract: **request parsing**
(the `paginate()` middleware stores structured query parameters at
`acc.paginate`) and **response metadata** (`send()` reads your handler's
`response.paginate` to auto-generate RFC 8288 Link headers and
`X-Total-Count`).

#### Offset Pagination

```js
router.get("/articles", {
  paginate: true,
  execute: async (req, res, acc) => {
    const { offset, limit } = acc.paginate;
    const items = await db.find(offset, limit);
    const total = await db.count();
    return {
      response: { body: items, paginate: { total } },
    };
  },
});
// GET /articles?page=2&per_page=10
// → Link: </articles?page=1&per_page=10>; rel="first", ...
// → X-Total-Count: 42
```

#### Cursor Pagination

```js
router.get("/events", {
  paginate: { strategy: "cursor" },
  execute: async (req, res, acc) => {
    const { cursor, limit } = acc.paginate;
    const { items, nextCursor } = await db.findAfter(cursor, limit);
    return {
      response: {
        body: items,
        paginate: { nextCursor },
      },
    };
  },
});
// GET /events?cursor=abc123&limit=10
// → Link: </events>; rel="first", </events?cursor=def456&limit=10>; rel="next"
```

<Aside type="tip" title="Automatic URL parsing">
  When `paginate` is set in the route config, ergo-router automatically
  includes `url()` parsing — you do not need to add `url: true`
  separately. The pipeline builder also auto-enables `send()`'s
  `paginate: true` option so Link headers are generated without
  additional configuration.
</Aside>

For pagination options (custom page sizes, maximum bounds) and the full
`acc.paginate` shape, see the
[paginate middleware guide](/middleware/paginate/). For end-to-end
examples including edge cases, see the
[Pagination recipe](/recipes/pagination/).

### Graceful Shutdown

`graceful(handler, options?)` creates an HTTP server with full lifecycle
management. It works with any `http.Server` handler — not coupled to
ergo-router.

```js
import createRouter, { graceful } from "@centralping/ergo-router";

const router = createRouter({ /* ... */ });

const { server, shutdown } = await graceful(router.handle(), {
  port: 3000,
  onStartup: async ({ log }) => {
    await connectDatabase();
    log.info("Database connected");
  },
  onShutdown: async ({ log, signal }) => {
    await disconnectDatabase();
    log.info("Cleanup complete");
  },
});
```

#### Options

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `port` | `number` | `3000` | Port to listen on |
| `hostname` | `string` | `'0.0.0.0'` | Hostname to bind to |
| `log` | `object` | `console` | Logger with `.info()`, `.warn()`, `.error()` methods |
| `signals` | `string[]` | `['SIGINT', 'SIGTERM']` | OS signals that trigger shutdown |
| `timeout` | `number` | `5000` | Maximum time (ms) to wait for connections to drain before forcing exit |
| `exit` | `function` | `process.exit` | Exit function (override for testing) |
| `onStartup` | `function` | — | Async hook called before `server.listen()`. Receives `{log}`. Rejection prevents the server from starting. |
| `onShutdown` | `function` | — | Async hook called after `server.close()`. Receives `{log, signal}`. Errors are caught and logged; shutdown continues. |

#### Return Value

Returns `Promise<{server, shutdown}>`:

- **`server`** — the `http.Server` instance
- **`shutdown`** — a function to trigger graceful shutdown programmatically (useful in tests)

#### Usage Examples

##### Custom Logger

Replace the default `console` with any object that provides `.info()`,
`.warn()`, and `.error()` methods — for example, a structured JSON logger:

```js
import createRouter, { graceful } from "@centralping/ergo-router";

const log = {
  info: (msg) => console.log(JSON.stringify({ level: "info", msg, ts: new Date().toISOString() })),
  warn: (msg) => console.log(JSON.stringify({ level: "warn", msg, ts: new Date().toISOString() })),
  error: (msg) => console.log(JSON.stringify({ level: "error", msg, ts: new Date().toISOString() })),
};

const router = createRouter({ /* ... */ });

await graceful(router.handle(), { port: 3000, log });
```

##### Testing with Programmatic Shutdown

Override `exit` to prevent `process.exit` during tests, use `port: 0` for an
ephemeral port, and call the returned `shutdown()` for cleanup:

```js
import { describe, it, after } from "node:test";
import assert from "node:assert/strict";
import { graceful } from "@centralping/ergo-router";

describe("server lifecycle", () => {
  let shutdown;

  after(async () => {
    if (shutdown) await shutdown("test-cleanup");
  });

  it("starts on an ephemeral port", async () => {
    const result = await graceful(
      (req, res) => { res.writeHead(200); res.end("ok"); },
      { port: 0, exit() {} },
    );
    shutdown = result.shutdown;

    const { port } = result.server.address();
    const res = await fetch(`http://localhost:${port}/`);
    assert.equal(res.status, 200);
  });
});
```
