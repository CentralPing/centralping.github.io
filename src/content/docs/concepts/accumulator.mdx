The [two-accumulator pipeline model](/concepts/architecture/) passes two
objects through every middleware in the chain: the **domain accumulator**
(`acc`) for inter-middleware data, and the **response accumulator** for
HTTP response properties. This page is the consolidated reference for
both.

## Domain Accumulator

Each domain-producing middleware carries an intrinsic accumulator path —
a non-enumerable `setPath` property set by the factory at creation time.
Built-in middleware can be composed as bare functions; custom middleware
uses `{fn, setPath}` config objects. The table below maps every
pipeline-builder key to its accumulator path and typed interface.

| Config Key | Accumulator Path (`acc.*`) | Type Interface | Pipeline Stage | Notes |
| --- | --- | --- | --- | --- |
| `tracing` | `trace` | [`TracingResult`](#acctrace) | Negotiation | Shortened — aligns with OpenTelemetry `trace` terminology |
| `logger` | `log` | [`LogEntry`](#acclog) | Negotiation | Shortened for ergonomics |
| `rateLimit` | `rateLimit` | — | Negotiation | |
| `accepts` | `accepts` | [`AcceptsResult`](#accaccepts) | Negotiation | |
| `preconditionRequired` | `precondition` | — | Negotiation | Shortened — the `Required` suffix describes the middleware's enforcement behavior, not the accumulator value |
| `cookie` | `cookies` | [`CookieJar`](#acccookies) | Negotiation | Pluralized — the jar holds multiple cookies |
| `url` | `url` | [`UrlResult`](#accurl) | Negotiation | |
| `paginate` | `paginate` | [`PaginateResult`](#accpaginate) | Negotiation | |
| `jsonApiQuery` | `jsonApiQuery` | — | Negotiation | |
| `prefer` | `prefer` | [`PreferResult`](#accprefer) | Negotiation | |
| `securityHeaders` | `security` | — | Negotiation | Shortened — config key names the middleware's concern (headers), setPath names the domain concept |
| `cacheControl` | `cache` | — | Negotiation | Shortened — `cacheControl` names the HTTP directive, `cache` names the domain concept |
| `csrf` | `csrf` | — | Authorization | |
| `authorization` | `auth` | [`AuthorizationResult`](#accauth) | Authorization | Shortened for ergonomics — `acc.auth` is accessed frequently in execute handlers |
| `body` | `body` | [`BodyResult`](#accbody) | Validation | |
| `idempotency` | `idempotency` | [`IdempotencyResult`](#accidempotency) | Validation | |
| `validate` | `validation` | — | Validation | Renamed — config key names the action (validate), setPath names the result (validation output) |

<Aside type="tip">
  Config keys marked **—** for Type Interface either produce response
  headers only (e.g. `securityHeaders`, `cacheControl`) or have
  minimal/internal accumulator values. See their individual guide pages
  for details.
</Aside>

<Aside type="caution" title="Config key ≠ accumulator path">
  Five config keys diverge from their accumulator path. Each divergence has a specific rationale — but with intrinsic paths, the middleware itself declares the correct path, so you rarely need to think about this mapping:

  - **`cookie`** → `acc.cookies` — pluralized because the jar holds multiple cookies
  - **`securityHeaders`** → `acc.security` — config key names the middleware's concern (HTTP headers), accumulator path names the broader domain concept
  - **`cacheControl`** → `acc.cache` — `cacheControl` is the HTTP directive name, `cache` is the domain concept
  - **`validate`** → `acc.validation` — config key names the action, accumulator path names the result
  - **`preconditionRequired`** → `acc.precondition` — the `Required` suffix describes enforcement behavior, not the accumulator value

  When using the [`validate` shorthand form](/middleware/validate/) (passing a raw JSON Schema directly), it resolves to `acc.validation.body` — the same path as the targeted `{body: schema}` form.
</Aside>

### `acc.url`

Stored at `acc.url` by the `url()` middleware. Parsed URL components using a fast
`indexOf` + `slice` parser.

```ts
interface UrlResult {
  query: Record<string, string | string[]>;
  pathname: string | undefined;
  search: string | undefined;
}
```

| Property | Type | Description |
| --- | --- | --- |
| `pathname` | `string \| undefined` | URL path before the query string |
| `search` | `string \| undefined` | Raw query string including leading `?`; `undefined` when absent |
| `query` | `Record<string, string \| string[]>` | Parsed query parameters (null-prototype object); multi-value keys become arrays |

[Full documentation →](/middleware/url/)

### `acc.paginate`

Stored at `acc.paginate` by the `paginate()` middleware. Parsed pagination parameters — a
discriminated union based on the active strategy.

```ts
type PaginateResult =
  | {strategy: 'offset'; page: number; perPage: number; offset: number; limit: number}
  | {strategy: 'cursor'; cursor: string | undefined; limit: number};
```

**Offset strategy:**

| Property | Type | Description |
| --- | --- | --- |
| `strategy` | `'offset'` | Active strategy identifier |
| `page` | `number` | Current page number (clamped to ≥ 1) |
| `perPage` | `number` | Items per page (clamped to ≤ `maxPerPage`) |
| `offset` | `number` | Computed: `(page - 1) * perPage` |
| `limit` | `number` | Same as `perPage` |

**Cursor strategy:**

| Property | Type | Description |
| --- | --- | --- |
| `strategy` | `'cursor'` | Active strategy identifier |
| `cursor` | `string \| undefined` | Opaque cursor token from query; `undefined` on first page |
| `limit` | `number` | Items to fetch (clamped to ≤ `maxLimit`) |

[Full documentation →](/middleware/paginate/)

<Aside type="note" title="Response-side contract">
  For `send()` to generate Link headers, your execute handler must return
  pagination metadata on the response: `{response: {body, paginate: {total}}}`
  for offset, or `{response: {body, paginate: {nextCursor}}}` for cursor.
  See [Pagination on the ergo-router page](/packages/ergo-router/#pagination)
  for the full two-sided contract, or the
  [Pagination recipe](/recipes/pagination/) for end-to-end examples.
</Aside>

### `acc.body`

Stored at `acc.body` by the `body()` middleware. Parsed request body with metadata.

```ts
interface BodyResult {
  type: string;
  charset: string;
  encoding: string;
  length: number | undefined;
  received: number;
  boundary: string | undefined;
  raw: string;
  parsed?: unknown;
}
```

| Property | Type | Description |
| --- | --- | --- |
| `type` | `string` | Content-Type MIME type |
| `charset` | `string` | Character encoding (e.g. `'utf-8'`) |
| `encoding` | `string` | Content-Encoding (e.g. `'identity'`, `'gzip'`) |
| `length` | `number \| undefined` | Content-Length header value; `undefined` for chunked |
| `received` | `number` | Actual bytes received |
| `boundary` | `string \| undefined` | Multipart boundary; `undefined` for non-multipart |
| `raw` | `string` | Raw body string before parsing |
| `parsed` | `unknown \| undefined` | Parsed body (JSON object, form data, etc.) |

[Full documentation →](/middleware/body/)

### `acc.cookies`

Stored at `acc.cookies` by the `cookie()` middleware. Cookie jar with incoming cookies as
own properties and methods for managing outgoing cookies.

```ts
interface CookieJar {
  set(name: string, value: string, options?: Record<string, unknown>): void;
  get(name: string): unknown;
  clear(name: string): void;
  toHeader(): string[];
  readonly size: number;
  readonly isJar: true;
  [name: string]: unknown;
}
```

Incoming cookies from the `Cookie` request header are available as own
properties on the jar (e.g. `acc.cookies.sessionId`). Outgoing cookies
are managed via `set()`, `get()`, `clear()`, and serialized to
`Set-Cookie` headers by `toHeader()`.

[Full documentation →](/middleware/cookie/)

### `acc.log`

Stored at `acc.log` by the `logger()` middleware. Structured request metadata captured at
pipeline entry.

```ts
interface LogEntry {
  requestId: string;
  timestamp: number;
  ip: string;
  method: string;
  url: string;
  httpVersion: string;
  host: Readonly<{
    hostname: string;
    arch: string;
    platform: string;
    pid: number;
 }>;
  request: {
    headers: Record<string, string | string[] | undefined>;
    encrypted: boolean;
    remoteAddress: string;
    remotePort: number;
  };
  traceId?: string;
  spanId?: string;
}
```

<Aside type="note">
  The `LogEntry` shown above is the **initial** shape available during
  pipeline execution. After the response `finish` event, `logger`
  appends response metadata (`statusCode`, `duration`, response
  headers) and emits the complete log entry.
</Aside>

[Full documentation →](/middleware/logger/)

### `acc.accepts`

Stored at `acc.accepts` by the `accepts()` middleware. Content negotiation results.

```ts
interface AcceptsResult {
  type: string | false;
  language: string | false;
  charset: string | false;
  encoding: string | false;
}
```

| Property | Type | Description |
| --- | --- | --- |
| `type` | `string \| false` | Best matching content type, or `false` if unacceptable |
| `language` | `string \| false` | Best matching language |
| `charset` | `string \| false` | Best matching charset |
| `encoding` | `string \| false` | Best matching encoding |

[Full documentation →](/middleware/accepts/)

### `acc.prefer`

Stored at `acc.prefer` by the `prefer()` middleware. Parsed [RFC 7240](https://www.rfc-editor.org/rfc/rfc7240) Prefer header as a
flat map.

```ts
interface PreferResult {
  [preference: string]: string | true;
}
```

Preference names map to their value string, or `true` for bare tokens.
Example: `{return: 'minimal', 'respond-async': true}`.

[Full documentation →](/middleware/prefer/)

### `acc.auth`

Stored at `acc.auth` by the `authorization()` middleware. The authenticated identity
returned by the matching strategy's authorizer function.

```ts
type AuthorizationResult = Record<string, unknown>;
```

The shape is **opaque** — it is entirely determined by the
user-provided `authorizer` function's `info` return value. The type
system represents this as `Record<string, unknown>`; consumers narrow
via application-level type assertions or generics.

**Common patterns:**

```js
// Bearer — authorizer returns user object
acc.auth  // → { user: { id: "42", role: "admin" } }

// Basic — authorizer returns credentials metadata
acc.auth  // → { username: "jane", permissions: ["read", "write"] }

// API Key — authorizer returns service identity
acc.auth  // → { service: "billing", scopes: ["invoices:read"] }
```

[Full documentation →](/middleware/authorization/)

### `acc.trace`

Stored at `acc.trace` by the `tracing()` middleware. OpenTelemetry span and context for
the current request.

```ts
interface TracingResult {
  span: import('@opentelemetry/api').Span;
  tracer?: import('@opentelemetry/api').Tracer;
  activeContext?: import('@opentelemetry/api').Context;
  parentContext: import('@opentelemetry/api').Context;
  traceId: string;
  spanId: string;
}
```

| Property | Type | Description |
| --- | --- | --- |
| `span` | `Span` | Active span for the request pipeline |
| `tracer` | `Tracer \| undefined` | Only populated when `perStage: true` |
| `activeContext` | `Context \| undefined` | Only populated when `perStage: true` |
| `parentContext` | `Context` | Parent context for child span creation |
| `traceId` | `string` | W3C trace ID (hex string) |
| `spanId` | `string` | Span ID (hex string) |

[Full documentation →](/middleware/tracing/)

### `acc.idempotency`

Stored at `acc.idempotency` by the `idempotency()` middleware. Idempotency-Key processing
result — a discriminated union with three variants.

```ts
type IdempotencyResult =
  | Record<string, never>
  | {key: string; fingerprint: string; complete: (response: unknown) => void; discard: () => void}
  | {replayed: true};
```

| Variant | When | Shape |
| --- | --- | --- |
| Empty object `{}` | No `Idempotency-Key` header present (and not required) | `Record<string, never>` |
| Active key | First request with this key — store the response when done | `{key, fingerprint, complete(), discard()}` |
| Replayed | Subsequent request with a completed key — response was replayed | `{replayed: true}` |

[Full documentation →](/middleware/idempotency/)

## ergo-router Seeds

When using `@centralping/ergo-router`, the domain accumulator is seeded
with route match data **before** the pipeline runs. These values are
available to all middleware and the `execute` handler.

### `acc.route.params`

Route parameters extracted by the router's path matching (powered by
`find-my-way`). Available immediately — not produced by a middleware
config object.

```js
// Route: "/users/:id/posts/:postId"
// Request: GET /users/42/posts/7

acc.route.params  // → { id: "42", postId: "7" }
```

Parameter values are always strings. Numeric conversion is the
consumer's responsibility.

## Response Accumulator

The response accumulator collects HTTP response properties set by
middleware. When any middleware sets `statusCode`, the pipeline breaks
immediately. After pipeline completion (or break), `send()` reads the
response accumulator to format the HTTP response.

```ts
interface ResponseAccumulator {
  statusCode?: number;
  headers?: [string, string][];
  body?: unknown;
  detail?: string;
  retryAfter?: number;
  instance?: string;
  location?: string;
  lastModified?: Date;
  type?: string;
  [key: string]: unknown;
}
```

| Property | Type | Description |
| --- | --- | --- |
| `statusCode` | `number` | HTTP status code — setting this breaks the pipeline |
| `headers` | `[string, string][]` | Response headers as `[name, value]` tuples (appended, not overwritten) |
| `body` | `unknown` | Response body (serialized by `send()`) |
| `detail` | `string` | [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) Problem Details `detail` field |
| `retryAfter` | `number` | `Retry-After` header value in seconds |
| `instance` | `string` | [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) `instance` URI |
| `location` | `string` | `Location` header value (redirects, 201 Created) |
| `lastModified` | `Date` | `Last-Modified` header value |
| `type` | `string` | [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) `type` URI |
