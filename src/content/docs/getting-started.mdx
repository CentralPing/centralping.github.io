## Prerequisites

- **Node.js 22** or later (pure ESM)
- **npm** (ships with Node.js)

## Installation

<Tabs>
  <TabItem label="Both packages">
    ```bash
    npm install @centralping/ergo @centralping/ergo-router
    ```
  </TabItem>
  <TabItem label="ergo only">
    ```bash
    npm install @centralping/ergo
    ```
  </TabItem>
</Tabs>

## Which Packages Do I Need?

| Use case | Packages | Why |
| --- | --- | --- |
| **Full REST API** with routing, transport security, and declarative pipeline assembly | `@centralping/ergo` + `@centralping/ergo-router` | ergo-router provides `createRouter()`, automatic `handler()`/`send()` wrapping, and transport-level concerns (request IDs, CORS, rate limiting, security headers) |
| **Custom routing** or framework integration — you bring your own router (Express, Fastify, Koa, etc.) | `@centralping/ergo` only | Use `compose()` and `handler()` directly to build pipelines without ergo-router's opinions |

<Aside type="tip">
  Most projects should start with **both packages**. Choose ergo-only when you
  need to integrate ergo middleware into an existing framework or want full
  control over routing and server lifecycle. See
  [Architecture](/concepts/architecture/) for a deeper look at how the two
  packages relate.
</Aside>

## Quick Start

Create a server with a single route that demonstrates all four Fast Fail
stages:

<Tabs>
  <TabItem label="JavaScript">
    ```js
    import createRouter, { graceful } from "@centralping/ergo-router";

    const router = createRouter({
      defaults: {
        accepts: { types: ["application/json"] },
      },
    });

    router.get("/users/:id", {
      authorization: {
        strategies: [
          {
            type: "Bearer",
            authorizer: async (attributes, token) => {
              if (!token) return { authorized: false };
              return { authorized: true, info: { userId: token } };
            },
          },
        ],
      },
      validate: {
        params: {
          type: "object",
          properties: { id: { type: "string", minLength: 1 } },
          required: ["id"],
        },
      },
      execute: (req, res, acc) => ({
        response: {
          body: {
            id: acc.route.params.id,
            name: "Jane Doe",
            requestedBy: acc.auth.userId,
          },
        },
      }),
    });

    router.post("/users", {
      authorization: {
        strategies: [
          {
            type: "Bearer",
            authorizer: async (attributes, token) => {
              if (!token) return { authorized: false };
              return { authorized: true, info: { userId: token } };
            },
          },
        ],
      },
      validate: {
        body: {
          type: "object",
          properties: { name: { type: "string", minLength: 1 } },
          required: ["name"],
        },
      },
      execute: (req, res, acc) => ({
        response: {
          statusCode: 201,
          body: { name: acc.body.parsed.name, createdBy: acc.auth.userId },
        },
      }),
    });

    await graceful(router.handle(), { port: 3000 });
    ```
  </TabItem>

            },

<Aside type="tip" title="Auto-included middleware">
  Some middleware is automatically included based on the HTTP method:

  - **URL parsing** (`url`) is auto-included for **GET** and **DELETE** routes — no explicit `url: true` needed.
  - **Body parsing** (`body`) is auto-included for **POST**, **PUT**, and **PATCH** routes — no explicit `body: true` needed.

  Setting the key to `false` disables auto-inclusion for that route.
</Aside>

<Aside type="tip" title="The execute function">
  The third argument (`acc`) is the **domain accumulator** — it carries
  middleware outputs (parsed body, auth identity, etc.) accumulated through the
  pipeline, plus route params seeded by the router (`acc.route.params`) before
  the pipeline runs. A fourth argument (response accumulator) is available for
  advanced use but rarely needed. See the
  [Accumulator Reference](/concepts/accumulator/) for the complete shape.
</Aside>

<Aside type="tip" title="The accumulator body object">
  The POST route above reads `acc.body.parsed` — the decoded JavaScript value
  from the request body. The full body result also includes `acc.body.raw` (the
  raw string, useful for signature verification) and metadata such as `type`,
  `charset`, `encoding`, `length`, and `received`. See the
  [ergo API reference](/api/ergo/centralping/ergo/) for the complete shape.
</Aside>

<Aside type="note" title="Transport vs. route-level middleware">
  The `defaults` key on `createRouter()` sets **route-level** middleware that
  runs after a route is matched. ergo-router also supports a `transport` key for
  **transport-level** middleware (request IDs, security headers, rate limiting,
  CORS) that runs on _every_ request — including 404 and 405 responses. See
  [Architecture — Shared Primitives](/concepts/architecture/#shared-primitives-lib)
  for more detail.
</Aside>

<Aside type="caution" title="Route config replaces defaults">
  When a route sets a config key that also appears in `defaults`, the route
  value **replaces** the default entirely — it does not merge. For example,
  setting `authorization: { strategies: [basicStrategy] }` on a route discards
  any strategies defined in `defaults.authorization`. See
  [Config Resolution](/packages/ergo-router/#config-resolution) for the full
  resolution rules and how to extend defaults with spread.
</Aside>

### What Happens

| Request | Result |
| ------- | ------ |
| `GET /users/42` with `Accept: text/xml` | **406 Not Acceptable** — negotiation fails |
| `GET /users/42` without `Authorization` | **401 Unauthorized** — authorization fails |
| `GET /users/42` with valid Bearer token | **200 OK** — all stages pass |
| `POST /users` without `Content-Type` | **415 Unsupported Media Type** — missing content type |
| `POST /users` with invalid JSON body | **400 Bad Request** — body parsing fails (malformed JSON) |
| `POST /users` with valid JSON + Bearer token | **201 Created** — resource created |

Every error response is a
[RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457) JSON object.

### Using ergo Without ergo-router

If you chose the **ergo-only** path, you compose middleware manually using
`compose()` and wrap the pipeline with `handler()`:

```js
import http from "node:http";
import { compose, handler, logger, url, accepts } from "@centralping/ergo";

const pipeline = compose(
  {fn: logger(), setPath: "log"},
  {fn: accepts({ types: ["application/json"] }), setPath: "accepts"},
  {fn: url(), setPath: "url"},
  (req, res, acc) => ({
    response: {
      body: { path: acc.url.pathname, query: acc.url.query },
      statusCode: 200,
    },
  }),
);

const server = http.createServer(handler(pipeline));
server.listen(3000, () => console.log("Listening on :3000"));
```

Middleware that writes to domain state is registered as a `{fn, setPath}` config
object — the function and the key under which its result is stored on the
[domain accumulator](/concepts/accumulator/). Response-only middleware and
validation gates can be plain functions. The final function in the pipeline is
the execute step: it reads accumulated values and returns a `{response}` object.

`handler()` creates both accumulators, runs the pipeline, and calls `send()`
exactly once to serialize the HTTP response. See the
[handler guide](/middleware/handler/) for all available options.
