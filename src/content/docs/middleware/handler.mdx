The HTTP request handler factory for ergo's two-accumulator model.
Creates [domain accumulator](/concepts/accumulator/) and response accumulator per request, runs the composed
pipeline, catches unexpected errors, and calls `send()` exactly once.
This is the standalone equivalent of ergo-router's `auto-wrap`.

**Pipeline stage:** Execution (wraps the entire pipeline)

## Import

```js
import {handler} from '@centralping/ergo';
```

## Arguments

| Argument | Type | Description |
| -------- | ---- | ----------- |
| `pipeline` | `function` | **Required.** Composed middleware pipeline |

## Options

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `debug` | `boolean` | `false` | Enable pipeline debug tracing. When true, `responseAcc._trace` is initialized with `{steps, breakAt}` before the pipeline runs. On error responses (≥ 400), `_trace` appears as an [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) extension member. |
| `onResponse` | `function` | — | Post-send lifecycle observation hook. Called after `send()` completes with `(req, res, responseInfo, domainAcc)`. Errors thrown by the hook are swallowed — the hook cannot affect the response. Async hooks are awaited. |
| `redactErrors` | `boolean` | `true` | Control whether caught 5xx exception messages appear in the [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) response `detail` field. When `true`, `detail` is set to generic status text. When `false`, `err.message` is passed through for 5xx only — 4xx always uses generic text. Stack traces are never exposed. Only set to `false` in development. |
| `timing` | `boolean \| object` | `false` | Inject an `X-Response-Time` header measuring the full request lifecycle (pipeline + error handling + send). Pass `true` for defaults (`x-response-time` header, 3 decimal places), or `{header?: string, precision?: number}` for custom configuration. Zero overhead when disabled. For router-level timing, see [Response Timing](/packages/ergo-router/#response-timing). |
| `prettify` | `boolean` | `false` | Pretty-print JSON output (forwarded to [send](/middleware/send/)) |
| `vary` | `string[]` | `['Accept']` | Vary header values to append (forwarded to [send](/middleware/send/)) |
| `etag` | `boolean` | `true` | Generate ETags and evaluate conditional headers (forwarded to [send](/middleware/send/)) |
| `prefer` | `boolean` | `false` | Read `domainAcc.prefer` for [RFC 7240](https://www.rfc-editor.org/rfc/rfc7240) `return=minimal` / `return=representation` (forwarded to [send](/middleware/send/)) |
| `paginate` | `boolean` | `false` | Read `domainAcc.paginate` and `responseAcc.paginate` to auto-generate [RFC 8288](https://www.rfc-editor.org/rfc/rfc8288) Link headers and `X-Total-Count` for paginated responses (forwarded to [send](/middleware/send/)) |
| `envelope` | `boolean \| function` | `false` | Wrap 2xx Object bodies in a response envelope (forwarded to [send](/middleware/send/)) |
| `errorFormatter` | `function` | — | Custom error body formatter for 4xx/5xx responses. Receives the [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) Problem Details object and `{requestId, statusCode, method}` context. Return value becomes the response body as `application/json` instead of `application/problem+json`. (forwarded to [send](/middleware/send/)) |
| `responseSchema` | `Record<number\|string, object>` | — | Map of status code to JSON Schema for response body projection (forwarded to [send](/middleware/send/)) |

<Aside type="caution" title="Header collision with custom middleware">
  When `timing` is enabled, the timing primitive patches `res.writeHead`
  to inject the response time header via `res.setHeader()` at
  header-flush time. If custom middleware also sets a header with the
  same name (default: `x-response-time`), the timing patch **silently
  overwrites** the custom value. To avoid the collision, either disable
  the built-in `timing` option and handle response timing entirely in
  your middleware, or configure a different header name via
  `timing: {header: 'x-custom-timing'}`.
</Aside>

## Return Value

Returns an async handler `(req, res) => void` suitable for
`http.createServer()`.

## Error Responses

| Status | Condition |
| ------ | --------- |
| **500 Internal Server Error** | Uncaught pipeline error (detail is redacted for security) |

## Usage

### Error Handling

- Sets `responseAcc.statusCode = 500` for uncaught pipeline errors
  (unless a timeout or earlier pipeline break already set the status)
- Attaches `instance` from the `X-Request-Id` response header
- Emits error on `res` if error listeners are present
- If `send()` itself throws: `res.statusCode = 500; res.end()`

<Aside type="tip">
For startup errors, runtime warnings, and troubleshooting, see [Debugging & Diagnostics](/concepts/debugging/).
</Aside>

### onResponse Hook

The `onResponse` option registers a post-send observation callback.
It fires after the HTTP response has been written — the hook cannot
alter headers, status, or body.

#### responseInfo Shape

| Field | Type | Description |
| ----- | ---- | ----------- |
| `statusCode` | `number` | Final HTTP status code |
| `headers` | `object` | Response headers snapshot (from `res.getHeaders()`) |
| `method` | `string` | Request HTTP method |
| `url` | `string` | Request URL |
| `bodySize` | `number \| undefined` | `Content-Length` value; `undefined` for stream bodies |
| `duration` | `number` | Pipeline execution time in milliseconds (from `performance.now()`) |

<Aside type="note" title="Error handling">
  Errors thrown by the `onResponse` hook are silently swallowed —
  the hook is for observation only and cannot affect the client
  response. Async hooks are awaited (the handler blocks until the
  hook completes or throws).
</Aside>

<Aside type="caution" title="bodySize for streams">
  When the response body is a stream, `Content-Length` is not set
  before piping begins. `bodySize` will be `undefined` in that case.
</Aside>

### Basic Usage

<Tabs>
  <TabItem label="Standalone">
    ```js
    import http from 'node:http';
    import {
      handler, compose, logger, authorization, body,
   } from '@centralping/ergo';

    const pipeline = compose(
      logger(),
      authorization({strategies}),
      body(),
      (req, res, acc) => ({
        response: {
          body: processRequest(acc),
          statusCode: 200,
       },
     }),
    );

    const server = http.createServer(
      handler(pipeline, {debug: true, prettify: true}),
    );
    server.listen(3000);
    ```
  </TabItem>
  <TabItem label="ergo-router">
    ```js
    // ergo-router uses auto-wrap internally — you don't call
    // handler() directly. The router's handle() method creates
    // the two-accumulator wrapper automatically.

    import createRouter, {graceful} from '@centralping/ergo-router';

    const router = createRouter();
    router.get('/health', {
      execute: () => ({response: {body: {ok: true}}}),
   });

    await graceful(router.handle(), {port: 3000});
    ```
  </TabItem>
